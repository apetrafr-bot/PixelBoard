# PixelBoard / Unity Editor protocol v1

All requests use HTTPS `POST /api/index.php?action=unity-ACTION`, JSON bodies.
Responses are JSON; errors have HTTP 4xx/5xx and `error`. Never retry writes with
a new operation ID after an uncertain result. All identifiers are case-sensitive.

## Browser account routes

Normal session cookie + `X-CSRF-Token`; owner required for pairing, revocation,
import creation/cancellation. Members may read snapshots and edit catalogue boards.

- `unity-pair-create` `{project_id, project_name}` -> `{pair_code, expires_at}`.
  Project ID is a stable UUID persisted privately by the Editor for this project.
  Code expires in 10 minutes, single use; owner obtains it on the website.
- `unity-revoke` `{project_id}` -> `{revoked:true}` (tokens and active jobs revoked).
- `unity-state` GET `&project_id=...` -> `{protocol:1, project, snapshot, jobs}`.
  Snapshot is null before first publication. Jobs expose IDs, state, result,
  dates, never tokens or hashes.
- `unity-request` `{project_id, request_id, kind:"refresh"|"import",
  catalogue_version, item_ids:[]}` -> `{job_id,state}`.
  Imports require owner and a current catalogue version. Server copies complete
  selected definitions plus schema into immutable job payload. Refresh requires
  a member session. `request_id` is a client-generated UUID and idempotency key.
- `unity-cancel` `{project_id,job_id}` -> `{cancelled:true}`, owner only.

## Editor routes

No browser cookie. `Authorization: Bearer TOKEN` required except claim pairing.
Server validates token, project, linked account still owner on every call.

- `unity-pair-claim` `{protocol:1,project_id,pair_code}` ->
  `{protocol:1,token,project_id}`. Store token privately outside Assets/Git.
- `unity-publish` `{protocol:1,project_id,snapshot}` -> `{accepted:true}`.
  Atomic complete snapshot, max 32 MiB JSON. No automatic catalogue overwrites.
- `unity-poll` `{protocol:1,project_id}` -> `{job:null|Job}`.
  Claims oldest queued job, or returns same active job on retries. Job expires
  after 24 hours; one active job per project.
- `unity-authorize` `{protocol:1,project_id,job_id}` ->
  `{authorized:true, payload:Payload}`. Call immediately before any asset writes,
  AFTER local user confirmation. Rechecks expiry, cancellation and current
  owner role; never treat earlier poll as write permission.
- `unity-result` `{protocol:1,project_id,job_id,state:"succeeded"|"failed"|"declined",
  result:{message,items:[{id,guid,file_id,fingerprint,status,message}]}}` ->
  `{accepted:true,state}`. Terminal result immutable; exact retries accepted.
  A successful import must be followed by a fresh snapshot publication.
  Successful entries use `status:"succeeded"` and all identity fields. Failed or
  uncertain entries may use `status:"failed"|"partial"` and `dirty:true`, without
  GUID/fileID/fingerprint. Interrupted writes must not be reported as successes.

`Job = {id,kind,state,expires_at,payload,payload_hash}`.
`payload_hash` is SHA256 of server-stored UTF8 compact JSON; compare opaque hash
and deep equality of payload between poll and authorize. Authorize also returns
`payload_hash`. Enum schema may include `flags:true`; `multiline` is UI metadata.
`Payload = {protocol:1,project_id,snapshot_hash,schema_hash,schema,items}`.
Refresh payload has empty items. Imported items are immutable approved website
definitions. Persist job IDs and write recovery/result journal in Editor before
writing; a repeated job must resend result, never recreate an asset. Server result
storage is outside board snapshots/restores.

## Snapshot and values

```
snapshot = {
  schema_hash: "sha256 hex", // hash of exact schema JSON generated by Editor
  schema: { families: [{type:"TilesClass"|"ToolClass"|"WeaponsClass"|"ArmureClass",
    fields:[Field]}] },
  assets:[{guid:"32 hex",file_id:"signed decimal string",name,type,path}],
  items:[{guid,file_id,type,name,fingerprint:"sha256 hex",values:{...}}],
  generated_at:"ISO8601"
}
Field = {name,label,kind,default,tooltip?,header?,type?,min?,max?,
         options?:[{name,value}],fields?:[Field],element?:Field}
```

Field names are serialized property names. Kind is `string`, `bool`, `int`,
`float`, `enum` (numeric value, including flags), `color` (object r/g/b/a),
`vector2`, `vector3`, `vector4` (objects x/y/z/w), `object` (fields),
`list` (element), `asset` (Unity object reference), or `unsupported`.
Null asset is JSON null. Asset value is `{guid,file_id}`; optional
`{item_id}` references a NEW catalogue item included in the same import.
Asset types use full Unity/C# type names; index may include compatible base-type
names in `types:[]`. Local fileID MUST remain a string (64-bit precision).
Enums use `options` name/value, NOT array indices. Unsupported values may be
preserved but must block import, never silently skipped.
Nested object/list values mirror the recursive field schema, NOT JSON text
embedded in strings. Defaults come from temporary ScriptableObject instances.
No arbitrary code, filesystem commands, or creation paths are accepted from site.
Existing identity uses GUID+fileID, with fingerprint for conflict detection.

Catalogue board: ID `__items__:<project_id>`, `recordType:"item-catalogue"`,
`projectId`, `schemaHash`, `items:[]` (board geometric items always empty),
`definitions:[{id,type,name,values,schemaHash,archived:false,
 unity:null|{guid,file_id,fingerprint}, revision:1}]`.
Linked card: `{type:"item-ref",itemId,projectId,...geometry}`.
IDs are stable UUIDs (server accepts 1–80 safe identifier chars). Definition
revision increases per edit. Existing values survive schema changes; explicit
user migration is needed. Old hash blocks import until schema reviewed.
Jobs use a copied definition shape above. Fingerprints must be checked in Unity
immediately before writes. Do not equate catalogue edit success, queued job,
authorization, or approval with a successful asset import.

Successful result entries bind their identity back to the original definition ID
under a workspace/board lock and increment its board version. Current values are
preserved if members edited the definition after approval. Partial/failed entries
never establish a success binding. State jobs expose `catalogue_notes:[]` for
missing/restored definitions or identity collisions requiring reconciliation.
This binding and the immutable terminal result commit atomically; an exact result
retry never changes the catalogue twice.

Optional `definition.illustration` is a bounded PNG/JPEG/WEBP data URL, a website
illustration only. It and `lastUnityValues` are omitted from job payloads. Field
identifiers `__proto__`, `prototype`, `constructor` are rejected. Object/list JSON
shapes, including empty objects, are preserved; PHP preserves zero-fraction float
defaults. Schema/fingerprint hashes remain Editor-generated opaque identities.
